## 问题一：私钥格式不兼容

### 问题描述

支付链接生成时报错：
```
request sign failed. Incorrect padding
```

### 根本原因

`alipay-sdk-python` SDK 内部使用 `rsa.PrivateKey.load_pkcs1()` 方法加载私钥，只能接受 **PKCS1 格式**私钥：

| 格式 | 标识 | 支持状态 |
|------|------|----------|
| PKCS1 | `-----BEGIN RSA PRIVATE KEY-----` | ✅ 支持 |
| PKCS8 | `-----BEGIN PRIVATE KEY-----` | ❌ 不支持 |

### 解决方案

将私钥转换为 PKCS1 格式，并更新所有相关配置。

### 修改的文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `keys/alipay_private_key_pkcs1.pem` | 新增 | PKCS1 格式私钥文件 |
| `.env` | 更新 | 私钥路径配置 |
| `.env.example` | 更新 | 私钥路径配置 |
| `src/config/settings.py` | 更新 | 默认私钥路径 |

## 问题二：自定义充值未调用真实支付接口

### 问题描述

使用自定义金额充值时，生成的支付链接是模拟链接 `https://pay.example.com/...`，而非真实的支付宝链接。

### 根本原因

`payment_service.py` 中的 `create_custom_recharge` 方法没有调用 `_generate_alipay_url()`，直接返回了模拟链接。

### 解决方案

修改 `src/services/payment_service.py` 中的 `create_custom_recharge` 方法：

```python
# 修改前
payment_url = f"https://pay.example.com/custom?order_no={order_no}&amount={amount}"

# 修改后
if payment_method == "alipay":
    payment_url = await self._generate_alipay_url(payment, None)
else:
    payment_url = f"https://pay.example.com/custom?order_no={order_no}&amount={amount}"
```

// 修改后

  // 尝试重新获取...

## 问题六：充值成功后账户余额未更新

### 问题描述

充值成功后，页面显示"充值成功"，但账户余额没有实时更新显示。

### 原因分析

1. 前端只调用了 `authApi.me()` 刷新用户信息
2. `User` 接口不包含 `balance` 字段
3. 没有调用 `/billing/account` 接口获取最新余额

### 解决方案

修改前端 `Recharge.tsx`，在充值成功后调用 `/billing/account` 获取最新余额：

```typescript
// 新增状态
const [currentBalance, setCurrentBalance] = useState<number | null>(null)

// 获取账户余额
const fetchBalance = async () => {
  try {
    const account = await billingApi.getAccount()
    setCurrentBalance(account.balance)
  } catch (error) {
    console.error('获取账户余额失败', error)
  }
}

// 在充值成功处理中添加
setPaySuccess(true)
fetchBalance()  // 获取最新余额
```

## 问题七：支付宝同步回调跳转处理

### 问题描述

支付宝支付成功后，跳转到 `/recharge` 页面，但没有正确处理同步回调参数，导致页面状态异常。

### 原因分析

1. 支付宝同步回调 URL 携带参数：`?out_trade_no=xxx&trade_status=TRADE_SUCCESS`
2. 前端没有解析这些参数
3. 用户体验不佳，不知道支付是否成功

### 解决方案

在 `Recharge.tsx` 中添加支付宝同步回调处理：

```typescript
// 检查是否是支付宝同步回调
const handleAlipayCallback = async () => {
  const outTradeNo = searchParams.get('out_trade_no')
  const tradeStatus = searchParams.get('trade_status')
  
  if (outTradeNo && tradeStatus === 'TRADE_SUCCESS') {
    // 显示加载状态
    setIsProcessingCallback(true)
    setPayModalVisible(true)
    
    // 查询支付状态
    const status = await paymentApi.getPaymentStatus(outTradeNo)
    
    if (status.status === 'paid' || status.status === 'completed') {
      setPaySuccess(true)
      fetchBalance()  // 获取最新余额
    }
    
    setIsProcessingCallback(false)
  }
}
```

## 问题八：支付成功后出现两个界面

### 问题描述

使用 `window.open` 打开支付宝支付页面后，支付成功跳转会打开新的工作台页面，导致：
1. 原工作台页面（带充值弹窗）仍然存在
2. 新打开的工作台页面也显示出来
3. 用户看到两个工作台界面

### 原因分析

1. 使用 `window.open()` 在新窗口中打开支付页面
2. 支付完成后，支付宝跳转到 `return_url`（工作台页面）
3. 新窗口显示工作台页面，但原窗口（工作台 + 充值弹窗）仍然存在

### 解决方案

**方案**：将 `window.open` 改为 `window.location.href`，在当前窗口跳转

```typescript
// 修改前（在新窗口打开）
window.open(currentPayment.pay_url, '_blank', 'width=800,height=600')

// 修改后（在当前窗口跳转）
window.location.href = currentPayment.pay_url
```

### 优点

1. **不会有多个界面**：支付完成后回调替换当前页面
2. **用户体验更好**：不需要在两个窗口之间切换
3. **关闭充值弹窗**：当前页面被替换，弹窗自动消失

### 注意事项

1. 支付宝沙箱可能无法正确跳转回 `localhost` 地址
2. 生产环境需要确保 `return_url` 配置正确
3. 如果浏览器阻止跳转，可以考虑降级为 `window.open`

### 修改文件

- `web/src/pages/developer/Recharge.tsx` - 支付跳转方式从 window.open 改为 window.location.href

## 问题九：充值成功后余额未更新

### 问题描述

充值成功后，页面显示"充值成功"，但余额没有实时更新显示。

### 原因分析

1. `setPaySuccess(true)` 和 `fetchBalance()` 同时执行
2. `useEffect` 监听 `paySuccess` 变化后立即执行跳转逻辑
3. 此时余额还没获取完成，导致余额显示为旧值或 null

### 解决方案

确保余额获取完成后再设置支付成功状态：

```typescript
// 修改前（同时执行）
setPaySuccess(true)
fetchBalance()  // 获取最新余额

// 修改后（先获取余额，再设置成功状态）
await fetchBalance()  // 先获取最新余额
setPaySuccess(true)    // 再设置支付成功状态
```

### 修改文件

- `web/src/pages/developer/Recharge.tsx` - 修改 handleAlipayCallback 中的执行顺序

## 问题十：充值成功后跳转目标错误

### 问题描述

开发者充值成功后，仍然跳转到 `/user` 页面，而不是开发者首页 `/`。

### 原因分析

1. 使用 `isNormalUser`（来自 React store 的旧状态）判断跳转目标
2. 支付宝回调回来时，store 中的用户信息可能还没更新
3. 导致跳转目标判断错误

### 解决方案

在 useEffect 中重新获取最新的用户信息：

```typescript
// 修改前
useEffect(() => {
  if (paySuccess) {
    if (isNormalUser) {
      navigate('/user')
    } else {
      window.location.href = '/'
    }
  }
}, [paySuccess])

// 修改后
useEffect(() => {
  if (paySuccess) {
    // 重新获取最新的用户信息，判断是否需要跳转
    const currentUser = useAuthStore.getState().user
    const isUserNormal = currentUser?.user_type === 'user'
    
    if (isUserNormal) {
      // 刷新用户信息
      const updatedUser = await authApi.me()
      useAuthStore.getState().setUser(updatedUser)
      
      // 根据最新的用户类型决定跳转目标
      if (updatedUser.user_type === 'developer' || updatedUser.user_type === 'owner') {
        navigate('/')
      } else {
        navigate('/user')
      }
    } else {
      window.location.reload()
    }
  }
}, [paySuccess])
```

## 问题十一：初始化执行顺序混乱

### 问题描述

页面初始化时，余额获取、套餐加载、支付宝回调处理等操作执行顺序混乱，导致状态不一致。

### 原因分析

1. `useEffect` 中的异步函数没有正确 await
2. `handleAlipayCallback()` 是 async 函数但直接调用，没有等待完成
3. 可能导致回调处理在余额获取之前完成

### 解决方案

使用 `Promise.all` 并行初始化，并正确 await 异步函数：

```typescript
// 修改前
useEffect(() => {
  fetchPackages()
  fetchConfig()
  fetchBalance()
  handleAlipayCallback()  // 没有 await
}, [])

// 修改后
useEffect(() => {
  const init = async () => {
    await Promise.all([
      fetchPackages(),
      fetchConfig(),
      fetchBalance(),
    ])
    // 检查是否是支付宝同步回调
    await handleAlipayCallback()
  }
  init()
}, [])
```

- `web/src/pages/developer/Recharge.tsx` - 修改初始化逻辑

## 问题十二：window.location.href 导致无法返回商户平台

### 问题描述

使用 `window.location.href` 跳转支付宝后，如果支付宝出错（如 AE0310600325 系统繁忙），用户无法返回商户平台页面。

### 原因分析

1. `window.location.href` 直接替换当前页面
2. 如果支付宝显示错误页面，用户只能关闭整个浏览器标签
3. 无法回到商户平台继续操作

### 解决方案

恢复 `window.open` 方式，同时添加窗口关闭检测：

```typescript
// 使用 window.open 在新窗口打开支付页面
const payWindow = window.open(currentPayment.pay_url, '_blank', 'width=800,height=600')

if (payWindow) {
  message.success({ content: '支付页面已打开，请在页面中完成支付' })
  
  // 监听支付窗口状态：如果用户关闭了支付窗口，检查支付状态
  const checkClosedInterval = setInterval(() => {
    if (payWindow.closed) {
      clearInterval(checkClosedInterval)
      // 用户关闭了支付窗口，检查支付状态
      handleRefreshStatus()
    }
  }, 1000)
} else {
  // 弹窗被浏览器阻止，提示用户
  message.warning('支付窗口被阻止，请允许弹窗后重试')
}
```

### 优点

1. **可返回**：用户可以关闭支付窗口回到商户平台
2. **自动刷新**：关闭支付窗口后自动检查支付状态
3. **错误处理**：如果支付宝出错，用户可以重试或取消订单

### 修改文件

- `web/src/pages/developer/Recharge.tsx` - 恢复 window.open 并添加窗口关闭检测

## 问题十四：自定义充值不支持扫码支付

### 问题描述

套餐充值可以选择扫码支付，但自定义充值（输入金额）只有跳转支付选项。

### 原因分析

1. `/create` 端点（套餐充值）支持扫码支付
2. `/custom` 端点（自定义充值）不支持扫码支付，没有生成二维码的逻辑

    payment_method: str = "alipay"
    payment_type: str = "page"  # page=跳转支付, qrcode=扫码支付

# 2. 在 /custom 端点中添加扫码支付逻辑
if request.payment_type == "qrcode" and request.payment_method == "alipay":
    try:
        qr_code = await service.generate_alipay_qrcode(payment)
        final_payment_url = None
    except Exception as e:
        logger.error(f"[CustomQRCode] 二维码生成失败: {str(e)}")

## 问题十五：跳转支付后支付宝窗口无法自动关闭

### 问题描述

使用跳转支付（点击"打开支付页面"）后，支付完成后支付宝窗口无法自动关闭。

### 原因分析

浏览器安全策略限制：JavaScript 无法关闭由不同域（跨域）打开的窗口。支付宝页面是由 `window.open()` 打开的，商户平台页面无法通过 `window.close()` 关闭它。

### 解决方案

在跳转支付的弹窗中添加提示文字：

```typescript
{/* 跳转支付：显示支付按钮 */}
<div className={styles.payActions}>
  <Alert 
    type="warning" 
    message="支付完成后，请手动关闭支付宝窗口" 
    showIcon 
    style={{ marginBottom: 16 }}
  />
  <Button ...>
    打开支付页面
  </Button>
</div>
```

### 备注

扫码支付不需要这个提示，因为二维码直接显示在商户平台页面，用户扫码后页面会自动轮询确认支付结果。

## 问题十六：前后端倒计时不同步导致刷新二维码失败

### 问题描述

用户点击"刷新二维码"按钮后，提示"二维码失效，请稍后重试"，但此时前端显示剩余有效期还有 9 分多钟（572秒）。

### 根本原因

前后端使用**不同的时间基准**计算订单有效期：

| 组件 | 计时逻辑 | 起始点 |
|------|----------|--------|
| **前端** | `countdown = 600`，页面加载时开始倒计时 | 本地页面加载时间 |
| **后端** | `created_at + 10分钟` | 数据库订单创建时间 |

**举例**：如果订单是 9 分钟前创建的，但用户刚打开页面：
- 前端显示：600 - 0 = **600 秒**（看起来还有10分钟）
- 后端检查：10分钟 - 9分钟 = **1 分钟**，**已过期！**

### 解决方案

1. **后端**：在订单创建和查询响应中添加 `created_at` 字段
2. **前端**：根据 `created_at` 计算剩余有效期，而非固定 600 秒

### 修改的文件

**`src/api/v1/payment.py`：**
```python
# 1. 在 CreatePaymentResponse 中添加 created_at
class CreatePaymentResponse(BaseModel):
    # ... 其他字段
    created_at: datetime  # 订单创建时间

# 2. 在 PaymentStatusResponse 中添加 created_at
class PaymentStatusResponse(BaseModel):
    # ... 其他字段
    created_at: datetime  # 订单创建时间

# 3. 返回时添加 created_at
return CreatePaymentResponse(
    created_at=payment.created_at,  # 新增
    # ... 其他字段
)
```

**`web/src/api/payment.ts`：**
```typescript
export interface PaymentStatus {
  // ... 其他字段
  created_at?: string  // 新增：订单创建时间
}
```

**`web/src/pages/developer/Recharge.tsx`：**
```typescript
// 添加计算剩余秒数的函数
const calculateRemainingSeconds = (createdAt: string): number => {
  const createdTime = new Date(createdAt).getTime()
  const now = Date.now()
  const EXPIRY_MINUTES = 10
  const expiryMs = EXPIRY_MINUTES * 60 * 1000
  return Math.max(0, Math.floor((createdTime + expiryMs - now) / 1000))
}

// 修改 setCountdown 调用
setCountdown(calculateRemainingSeconds(payment.created_at))
```
