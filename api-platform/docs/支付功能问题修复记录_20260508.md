## 问题一：Python 缓存导致服务加载旧代码

### 现象
服务日志显示 `NameError: name 'logger' is not defined`，但代码中 logger 已定义。

### 根本原因
Python 的 `__pycache__` 缓存了旧版本的模块，导致服务加载的是未定义 logger 的旧代码。

### 解决步骤
1. 停止所有 Python 进程
2. 清除所有 `__pycache__` 目录
3. 重新启动服务（使用 `--reload` 参数）

### 预防措施
- 修改代码后，如果服务没有自动重载，需手动重启
- 定期清理 `__pycache__` 缓存

## 问题二：支付宝回调签名验证失败

### 现象
- 支付宝扫码付款成功
- 支付宝回调返回 `{"success": false, "message": ""}`

**错误位置**: `src/api/v1/payment.py` 约第 654 行

**错误代码**:
```python
sign_content = "&".join(sign_parts)
is_valid = verify_with_rsa(settings.get_alipay_public_key(), sign_content, signature)
```

**修复代码**:
```python
sign_content = "&".join(sign_parts)

# 验证签名：verify_with_rsa 需要 message 是有 read() 方法的对象
from io import BytesIO
message_stream = BytesIO(sign_content.encode('utf-8'))
is_valid = verify_with_rsa(settings.get_alipay_public_key(), message_stream, signature)
```

## 问题六：二维码倒计时显示为0秒（时区混淆bug）

### 现象
- 点击"立即充值"后，页面显示"二维码有效期：0秒"
- 用户还未来得及扫码支付，二维码就已过期

### 根本原因
**时区混淆bug**：`calculate_expires_in` 函数假设 naive datetime 是本地时间（UTC+8），但数据库实际存储的是 UTC 时间，导致时间计算错误。

### 修复方案
`calculate_expires_in` 函数将 naive datetime 假定为 **UTC 时间**（与数据库实际存储一致），并添加防御性检查和日志：

```python
def calculate_expires_in(created_at: datetime) -> int:
    if created_at is None:
        return 600  # 默认值
    
    now_utc = utc_now()
    
    if created_at.tzinfo is None:
        # 假定为 UTC 时间
        utc_tz = timezone.utc
        created_at_aware = created_at.replace(tzinfo=utc_tz)
    else:
        created_at_aware = created_at
    
    expiry_time = created_at_aware + timedelta(minutes=ORDER_EXPIRY_MINUTES)
    remaining = (expiry_time - now_utc).total_seconds()
    
    # 异常检查
    if remaining > ORDER_EXPIRY_MINUTES * 60 * 2 or remaining < 0:
        return 600
    
    return max(0, int(remaining))
```

```typescript
export function formatLocalDateTime(utcString: string, format: string = 'YYYY-MM-DD HH:mm:ss'): string {
  const date = new Date(utcString)
  if (isNaN(date.getTime())) return '-'
  
  // 提取本地时间并格式化
  const year = date.getFullYear()
  const month = String(date.getMonth() + 1).padStart(2, '0')
  const day = String(date.getDate()).padStart(2, '0')
  const hours = String(date.getHours()).padStart(2, '0')
  const minutes = String(date.getMinutes()).padStart(2, '0')
  const seconds = String(date.getSeconds()).padStart(2, '0')
  
  return format.replace('YYYY', year).replace('MM', month)...
}
```

## 问题五：React 状态异步导致轮询循环立即退出

### 现象
- `[DEBUG] startQrcodePolling 函数被调用` 日志正常输出
- **没有** `[QRCode Poll] 第 1 次` 日志
- 轮询循环根本没有执行

### 根本原因
React 状态更新是**异步**的！

```typescript
const startQrcodePolling = async (paymentNo: string) => {
  setQrcodePolling(true)  // 异步！不会立即生效
  const intervals = [...]
  
  for (let i = 0; i < intervals.length; i++) {
    if (!qrcodePolling) break  // ❌ 检查时还是 false，立即退出循环
    // ...
  }
}
```

### 修复方案
使用**局部变量**替代 React 状态来控制循环：

```typescript
const startQrcodePolling = async (paymentNo: string) => {
  setQrcodePolling(true)
  let isPolling = true  // ✅ 局部变量，立即生效
  const intervals = [2000, 2000, 2000, 3000, 3000, 5000, 5000, 10000]
  
  for (let i = 0; i < intervals.length; i++) {
    if (!isPolling) break  // ✅ 现在检查的是局部变量
    // ...
    if (status.status === 'completed') {
      isPolling = false
      setQrcodePolling(false)  // 循环结束后再更新状态
      handleQrcodePaymentSuccess(status)
      return
    }
    // ...
  }
}
```

### 跳转支付是否有同样问题？
**没有**。跳转支付 `handleAlipayCallback` 内部定义了 `pollPaymentStatus` 函数，使用的是局部变量 `intervals`，不受 React 状态异步影响。

### 相关文件
- `web/src/pages/developer/Recharge.tsx`

### 经验总结
1. **React 状态更新是批处理异步的**：调用 `setState` 后立即读取，值可能还没更新
2. **轮询循环不要依赖外部状态作为退出条件**：使用局部变量
3. **正确模式**：`setState(true)` + `let isRunning = true` + `if (!isRunning) break`

---

### 时区处理经验总结
1. **统一使用 UTC 存储**：数据库中的时间字段应统一存储为 UTC 时间
2. **数据库连接层强制时区**：在 `create_engine` 中使用 `connect_args={"options": "-c timezone=utc"}` 强制数据库使用 UTC
3. **不要依赖假设**：不要假设 naive datetime 是 UTC 还是本地时间，应该在数据库连接层面统一
4. **前端显示时转换**：在需要显示给用户时，再将 UTC 时间转换为本地时区
5. **添加调试日志**：时区问题很难排查，应该在关键位置添加日志

## 问题四：JavaScript 函数定义顺序问题（变量提升）

### 现象
- 前端代码已添加 `startQrcodePolling()` 调用
- 控制台没有 `[DEBUG]` 日志输出
- 后端日志显示只有手动刷新，没有自动轮询

### 根本原因
**JavaScript/TypeScript 中，`const` 和 `let` 声明的函数表达式不会提升（hoisting）**。

函数定义顺序：
```
handleCreateOrder (443行) → 调用 startQrcodePolling → 运行时 startQrcodePolling = undefined ❌
startQrcodePolling (549行) → 函数定义位置
```

由于 `startQrcodePolling` 在 `handleCreateOrder` **之后**定义，调用时它是 `undefined`，导致静默失败（不会报错）。

### 修复方案
将 `startQrcodePolling` 和 `handleQrcodePaymentSuccess` 函数移到 `handleCreateOrder` **之前**定义。

**正确顺序**：
```typescript
// 第 388 行：先定义轮询函数
const startQrcodePolling = async (paymentNo: string) => { ... }

// 第 420 行
const handleQrcodePaymentSuccess = async (status: any) => { ... }

// 第 443 行：再定义使用轮询的函数
const handleCreateOrder = async () => {
    // ...
    startQrcodePolling(payment.payment_no) // 现在可以正常调用 ✅
}
```

### 相关文件
- `web/src/pages/developer/Recharge.tsx`

### 经验总结
1. **ES6 `const/let` 不 hoist**：使用 `const` 声明的箭头函数不会被提升
2. **函数声明 `function` 会 hoist**：传统 `function fn() {}` 可以放在调用之后
3. **最佳实践**：将辅助函数（特别是被其他函数调用的）放在文件顶部或使用前定义

## 问题八：跳转支付窗口关闭后无法自动回调

### 现象
- 用户使用跳转支付（在新窗口打开支付宝）
- 用户完成支付后，支付宝跳转到 PaymentSuccess 页面
- 用户点击"关闭此页面"，窗口关闭
- **父窗口（Recharge 页面）没有自动收到支付结果**，用户需要手动点击"刷新状态"

### 根本原因分析

#### 原因一：postMessage 无法工作
支付成功页面（PaymentSuccess）关闭时，无法通过 `postMessage` 将消息传递给父窗口，因为：
1. 支付宝的 return_url 跳转后，`window.opener` 指向的是支付宝页面，不是我们的 Recharge 页面
2. 跨窗口通信失败

#### 原因二：localStorage 无法跨域名共享（关键问题）
**第一版修复尝试使用 `localStorage` 作为跨窗口通信中介，但失败了！**

原因是：
- Recharge 页面在 `localhost:3000`（或 ngrok 的公网地址，如 `trycloudflare.com`）
- PaymentSuccess 页面在 `trycloudflare.com`（支付宝 return_url 跳转后的页面）
- **两个页面域名不同！**

**`localStorage` 受同源策略（Same-Origin Policy）限制**，同一域名下的页面才能共享 localStorage 数据。不同域名之间无法互相读取对方的 localStorage。

```
localhost:3000 (Recharge)  ←→  trycloudflare.com (PaymentSuccess)
         ↓                              ↓
    localStorage A                localStorage B (不互通！)
```

#### 原因三：focus 事件不触发
**第二版修复尝试使用 `focus` 事件，但仍然失败！**

问题是：当用户关闭 PaymentSuccess 窗口时，浏览器**不会自动将焦点返回给 Recharge 页面**，`focus` 事件不会触发。

### 最终解决方案：支付结果轮询机制

采用**定时轮询**方案作为最可靠的检测机制：

```typescript
// 【新增】轮询定时器 ref，用于检测支付结果
const paymentPollIntervalRef = useRef<NodeJS.Timeout | null>(null)

// 【新增】启动支付结果轮询
const startPaymentPoll = () => {
  if (paymentPollIntervalRef.current) return  // 避免重复启动
  
  console.log('[Recharge] 启动支付结果轮询')
  paymentPollIntervalRef.current = setInterval(() => {
    const state = paymentStateRef.current
    
    // 只在弹窗打开、未成功、有支付信息时才查询
    if (state.payModalVisible && !state.paySuccess && state.currentPayment) {
      const payment = state.currentPayment
      if (payment.status === 'pending') {
        console.log('[Recharge] 轮询查询支付状态...')
        handleRefreshStatus()
      }
    } else {
      stopPaymentPoll()  // 条件不满足，停止轮询
    }
  }, 3000)  // 每 3 秒查询一次
}

// 【新增】停止支付结果轮询
const stopPaymentPoll = () => {
  if (paymentPollIntervalRef.current) {
    clearInterval(paymentPollIntervalRef.current)
    paymentPollIntervalRef.current = null
  }
}
```

### 轮询触发时机

| 场景 | 是否启动轮询 |
|------|------------|
| 扫码支付（qrcode 模式） | ❌ 不启动（已有独立的 startQrcodePolling） |
| 跳转支付（page 模式） | ✅ 启动轮询 |

### 轮询停止时机

| 场景 | 是否停止轮询 |
|------|------------|
| 用户关闭弹窗 | ✅ 停止 |
| 支付成功检测到 | ✅ 停止 |
| 订单过期 | ✅ 停止 |
| 页面刷新 | ✅ 停止（组件卸载） |

### 使用 ref 避免闭包问题

React 的 useEffect 闭包可能导致事件处理器中访问到旧的状态值。使用 `useRef` 解决：

```typescript
// 使用 ref 跟踪最新状态
const paymentStateRef = useRef<{
  currentPayment: Payment | null
  payModalVisible: boolean
  paySuccess: boolean
}>({ currentPayment: null, payModalVisible: false, paySuccess: false })

// 每次 state 变化时同步到 ref
useEffect(() => {
  paymentStateRef.current = { currentPayment, payModalVisible, paySuccess }
}, [currentPayment, payModalVisible, paySuccess])

// 事件处理器中使用 ref 获取最新值
const handleWindowFocus = () => {
  const state = paymentStateRef.current  // 始终是最新的！
  // ...
}
```

```typescript
const handleStorageChange = (event: StorageEvent) => {
  if (event.key === 'payment_success_result' && event.newValue) {

    if (result.status === 'paid' || result.status === 'completed') {

      fetchBalance()
      setPayModalVisible(false)

    }

  }
}
```

## 问题九：focus 事件影响二维码支付流程

### 现象
- 二维码支付使用独立的轮询机制（`startQrcodePolling`）
- 当用户切换到其他标签页再切回来时，`focus` 事件触发
- 如果此时 localStorage 中有跳转支付的残留数据，可能导致错误处理

### 根本原因
`checkPaymentResult` 函数会检查 `localStorage` 中的 `payment_success_result`，但没有区分当前是二维码支付还是跳转支付模式。

### 解决方案
在 `checkPaymentResult` 函数中增加检查，只在跳转支付模式下（没有二维码）才处理 localStorage 结果：

```typescript
const checkPaymentResult = () => {
  // 【关键修复】只有在跳转支付模式下（没有二维码）才处理 localStorage 结果
  // 二维码支付有独立的轮询机制（startQrcodePolling），不受此影响
  if (currentPayment?.qr_code) {
    console.log('[Recharge] checkPaymentResult 跳过：二维码支付模式，无需处理 localStorage')
    return
  }
  // ... 后续处理逻辑
}
```

### 为什么这样设计？

| 支付类型 | 检测机制 | 处理方式 |
|---------|---------|---------|
| 二维码支付 | `startQrcodePolling` 轮询 | 通过轮询直接检测支付状态，不依赖 localStorage |
| 跳转支付 | `focus`/`visibilitychange` 事件 | 检测窗口获得焦点后，读取 localStorage 中的支付结果 |

## 问题十：充值记录时区错误

**日期**: 2026-05-09
**问题类型**: 数据库时区存储问题

### 现象
- 充值记录的时间比实际时间早 8 小时
- 例如：实际充值时间 23:46，显示为 15:46

### 根本原因
数据库存储的是 CST（中国标准时间，UTC+8），但没有正确处理时区转换：
- CST 时间被错误地当作 UTC 存储
- 导致前端显示时比实际时间少 8 小时

### 影响范围
| 环境 | 错误记录数 |
|------|-----------|
| production | 27 条 |
| simulation | 17 条 |

### 数据修复 SQL
`sql
-- 修复 production 环境
UPDATE bills 
SET created_at = created_at + INTERVAL '8 hours'
WHERE bill_type = 'recharge'
    AND environment = 'production'
    AND EXTRACT(HOUR FROM created_at) BETWEEN 14 AND 16;

-- 修复 simulation 环境
UPDATE bills 
SET created_at = created_at + INTERVAL '8 hours'
WHERE bill_type = 'recharge'
    AND environment = 'simulation'
    AND EXTRACT(HOUR FROM created_at) BETWEEN 6 AND 12;
`

### 代码修复
**文件**: src/config/database.py
- 设置会话时区为 UTC

**文件**: src/services/billing_service.py
- CSV 导出使用正确的时区转换

## 问题十一：充值账单 transaction_id 全为 NULL

**日期**: 2026-05-09
**问题类型**: 数据关联缺失

### 现象
- bills 表的 transaction_id 字段全部为 NULL
- 充值账单没有关联到支付记录的第三方交易号

### 根本原因
ccount_service.py 的 dd_balance 方法创建 Bill 时没有设置 	ransaction_id 参数。

### 数据关联关系
`
bills.source_id -> payments.id
bills.transaction_id <- payments.transaction_id
`

### 历史数据修复 SQL
`sql
UPDATE bills b
SET transaction_id = p.transaction_id
FROM payments p
WHERE b.source_id = p.id::text
    AND b.bill_type = 'recharge'
    AND b.transaction_id IS NULL
    AND p.transaction_id IS NOT NULL;
`
**修复结果**: 83 条记录已关联

### 代码修复

**文件**: src/services/account_service.py
- dd_balance 方法添加 	ransaction_id 参数

`python
async def add_balance(

    user_id: str,
