### N-1 | ⚠️ 抓到一个真实的"重复请求"缺陷（先让测试说出真相）

- **做法**：先写"首屏只应拉一次账单"的断言，**不改代码**，跑出证据。
- **失败原文**（日志 `16-N轮-Billing三跑.log`）：
  ```
  AssertionError: expected "spy" to be called 1 times, but got 2 times
  ```
- **根因**：本页有两个 effect 都会拉账单 ——
  `fetchData()`（内部调用 `fetchBills()`）与 `useEffect(fetchBills, [page,pageSize,dateRange])`；
  挂载时两者都触发 → 首屏账单被请求 2 次。
- **修法**：把 `fetchBills()` 从 `fetchData()` 中摘出，新增 `handleRefresh()` 让「刷新」按钮
  同时重拉概览与账单（保持手动刷新语义不变），首屏由单一 effect 负责。
- **复跑**（日志 `17-N轮-Billing四跑.log`）：`6 passed` ✅

### N-2 | 顺带修一处金额显示顺序

金额列原写法 `{amount>=0?'+':''}¥{amount.toFixed(2)}` → 负数渲染为 **`¥-12.50`**
（符号夹在货币符号之后）。补测时由断言 `-¥12.50` 失败暴露，已改为
`{amount>=0?'+':'-'}¥{Math.abs(amount).toFixed(2)}`（桌面表格 + 移动端卡片同步）；
另清移动端 `Card bodyStyle`。

### N-3 | 三个 jsdom 技法（本轮新踩）

① **同一文案既是"类型标签"又是"页面按钮"时要按行作用域断言**：`充值` 同时是账单类型 Tag
   与顶部充值按钮 → 全局 `getByText('充值')` 报多元素（首跑即此错）→ 改为
   `within(该行 tr).getByText(...)`；并让 mock 的描述文案与类型文案**不重叠**（`会员充值` vs `充值`）。
