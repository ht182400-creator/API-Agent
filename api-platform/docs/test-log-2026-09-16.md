### B-3 | ANA-008 第二轮修复（mouseDown 触发）→ 仍失败

- **改动**：`pick()` 改用 `fireEvent.mouseDown(selector)` 打开下拉（antd 官方测试写法）。
- **结果**：仍 `Unable to find role="option" and name "待审核"`（原始输出：`22-ANA008-motion关闭后.log`）。
- **追加实验**：`renderPage()` 包 `ConfigProvider motion:false`（与 renderWithProviders 对齐）→ 仍失败。

### B-4 | ANA-008 深挖：DOM dump 定位真因（**不猜，看 DOM**）

- **手段**：临时在 `pick()` 里 dump `document.querySelectorAll('.ant-select-dropdown')` 的
  className / aria-expanded / option 数与文本（原始输出：`21-…DOMdump.log`、`23-…option渲染诊断.log`）。
- **发现**：
  1. 下拉**已打开**（`aria-expanded: true`、弹层存在）；
  2. className 停在 `ant-slide-up-appear-prepare`（**motion 动画帧卡住**，jsdom 无 transitionend）；
  3. **option 渲染完全正常**（5 个：全部状态/已上线/待审核/已下线/已拒绝）。
- **结论**：`findByRole('option')` 找不到不是"没渲染"，而是 **RTL 的可访问性判定**：
  弹层容器卡在动画帧被视为不可见（`ConfigProvider motion:false` 的 token **禁不掉** rc-motion 的 slide-up）。
- **修法**：绕开可访问性查询 —— `mouseDown` 打开 → 在未 hidden 的弹层里按文本找
  `.ant-select-item-option` → `fireEvent.click`（不做可见性检查，onSelect 照常触发）。
- **复跑**：`Analytics.spec 8 passed`（`24-ANA008-DOM选option.log`）✅
