# 支付流程文档

## 一、概述

系统支持两种支付方式：**二维码支付**（扫码支付）和**跳转支付**（支付链接跳转）。每种支付方式有独立的轮询机制来检测支付状态。

## 二、支付方式对比

| 特性 | 二维码支付 | 跳转支付 |
|------|-----------|---------|
| 触发条件 | `paymentType === 'qrcode' && payment.qr_code` 存在 | 其他情况（跳转链接） |
| 轮询函数 | `startQrcodePolling()` | `startPaymentPoll()` |
| 轮询间隔 | 递进式：2s×3, 3s×2, 5s×2, 10s×1（共约40秒） | 每3秒一次（持续轮询） |
| 状态查询 | `handleQrcodePaymentStatus()` | `handleRefreshStatus()` |
| 成功处理 | `handleQrcodePaymentSuccess()` | `handleRefreshStatus()` 内部处理 |
| 检测方式 | 后端轮询 | 后端轮询 + localStorage 监听 |
| 错误提示 | 通过 `setPayError()` 设置 | 通过 `showError` 参数控制 |

## 三、二维码支付流程

### 3.1 流程图

```
用户选择套餐 → 创建订单 → 显示二维码 → 启动轮询 → 支付成功 → 关闭弹窗 → 刷新页面
                              ↓
                        轮询检测状态（最多8次，约40秒）
                              ↓
                         超时 → 显示超时错误
```

### 3.2 代码实现

```typescript
// Recharge.tsx - handleCreateOrder
if (paymentType === 'qrcode' && payment.qr_code) {
  startQrcodePolling(payment.payment_no)
} else {
  startPaymentPoll()
}
```

### 3.3 轮询机制 (`startQrcodePolling`)

```typescript
const startQrcodePolling = async (paymentNo: string) => {
  setQrcodePolling(true)
  let isPolling = true
  // 递进式间隔：短→长，给用户充足时间支付
  const intervals = [2000, 2000, 2000, 3000, 3000, 5000, 5000, 10000]
  
  for (let i = 0; i < intervals.length; i++) {
    if (!isPolling) break // 用户关闭弹窗时停止
    
    await new Promise(resolve => setTimeout(resolve, intervals[i]))
    
    const status = await paymentApi.getPaymentStatus(paymentNo)
    
    if (status.status === 'paid' || status.status === 'completed') {
      // 支付成功处理
      setPaySuccess(true)
      setQrcodePolling(false)
      handleQrcodePaymentSuccess(status)
      return
    }
  }
  
  // 轮询耗尽，超时处理
  setQrcodePolling(false)
  setPayError('支付超时，请刷新页面重试')
}
```

### 3.4 关键特性

- **独立轮询**：二维码支付使用独立的 `startQrcodePolling`，不受 `startPaymentPoll` 影响
- **递进间隔**：2s → 2s → 2s → 3s → 3s → 5s → 5s → 10s，总计约40秒
- **弹窗关闭检测**：通过 `paymentStateRef.current.payModalVisible` 检测弹窗是否关闭
- **不依赖 localStorage**：二维码支付不监听 `localStorage` 变化

## 四、跳转支付流程

### 4.1 流程图

```
用户选择套餐 → 创建订单 → 打开支付页面 → 启动轮询 → 监听窗口关闭 → 支付成功/返回 → 关闭弹窗 → 刷新页面
                                          ↓
                                    每3秒轮询检测
                                          ↓
                                    localStorage 监听
```

### 4.2 代码实现

```typescript
// Recharge.tsx - handleCreateOrder
if (paymentType === 'qrcode' && payment.qr_code) {
  startQrcodePolling(payment.payment_no)
} else {
  // 跳转支付模式：启动支付结果轮询作为后备
  startPaymentPoll()
}
```

### 4.3 轮询机制 (`startPaymentPoll`)

```typescript
const startPaymentPoll = () => {
  if (paymentPollIntervalRef.current) return // 防止重复启动
  
  paymentPollIntervalRef.current = setInterval(() => {
    const state = paymentStateRef.current
    
    // 只在弹窗打开、未成功、有支付信息时才查询
    if (state.payModalVisible && !state.paySuccess && state.currentPayment) {
      const payment = state.currentPayment
      if (payment.status === 'pending') {
        // 【优化】自动轮询时不显示错误提示，避免干扰用户
        handleRefreshStatus(false)
      }
    } else {
      stopPaymentPoll() // 条件不满足时停止轮询
    }
  }, 3000) // 每3秒查询一次
}
```

### 4.4 窗口关闭检测

```typescript
// 监听支付窗口状态
payWindowIntervalRef.current = setInterval(() => {
  if (payWindow.closed) {
    clearInterval(payWindowIntervalRef.current)
    payWindowIntervalRef.current = null
    // 用户关闭了支付窗口，自动刷新支付状态（不显示错误提示）
    handleRefreshStatus(false)
  }
}, 1000)
```

### 4.5 localStorage 监听

```typescript
// PaymentSuccess.tsx - 支付成功后
localStorage.setItem('payment_success_result', JSON.stringify({
  outTradeNo: response.payment_no || response.order_no,
  status: 'paid',
  amount: amount,
  timestamp: Date.now()
}))

// Recharge.tsx - 监听 localStorage 变化
window.addEventListener('storage', (e) => {
  if (e.key === 'payment_success_result') {
    checkPaymentResult()
  }
})
```

## 五、状态检测函数 (`handleRefreshStatus`)

### 5.1 函数签名

```typescript
const handleRefreshStatus = async (showError: boolean = true) => {
  // showError: 是否显示错误提示
  // - true: 用户主动操作（如点击"刷新状态"按钮）
  // - false: 自动轮询、窗口关闭检测等自动行为
}
```

### 5.2 处理逻辑

```typescript
const handleRefreshStatus = async (showError: boolean = true) => {
  // 1. 检查 currentPayment 是否存在
  if (!currentPayment) {
    const urlOutTradeNo = searchParams.get('out_trade_no')
    if (urlOutTradeNo) {
      // 使用 URL 中的订单号
      setCurrentPayment({
        payment_no: '',
        order_no: urlOutTradeNo,
        status: 'pending'
      } as Payment)
    } else {
      // 【优化】自动轮询时不显示"没有支付信息"提示
      if (showError) {
        message.error('没有支付信息')
      }
      return
    }
  }
  
  // 2. 查询支付状态
  const queryKey = currentPayment.payment_no || currentPayment.order_no
  const status = await paymentApi.getPaymentStatus(queryKey)
  
  // 3. 更新状态
  setCurrentPayment(status)
  
  // 4. 支付成功处理
  if (status.status === 'paid' || status.status === 'completed') {
    setPaySuccess(true)
    stopPaymentPoll()
    setPayModalVisible(false)
    message.success('支付成功')
    window.location.reload()
  }
}
```

## 六、弹窗关闭处理 (`handlePayModalClose`)

### 6.1 代码实现

```typescript
const handlePayModalClose = () => {
  // 【修复】关闭弹窗时停止所有轮询
  stopPaymentPoll()                          // 停止跳转支付轮询
  if (payWindowIntervalRef.current) {       // 停止窗口检测
    clearInterval(payWindowIntervalRef.current)
    payWindowIntervalRef.current = null
  }
  stopQrcodePolling()                        // 停止二维码轮询
  
  setPayModalVisible(false)
  setPayError(null)
  clearUrlParams()
}
```

### 6.2 重要性

- 防止弹窗关闭后继续触发错误提示
- 释放资源（停止定时器）
- 清理 URL 参数

## 七、错误处理对比

| 场景 | 二维码支付 | 跳转支付 |
|------|-----------|---------|
| 轮询失败 | 通过 `setPayError()` 显示 | 通过 `showError` 参数控制 |
| "没有支付信息" | 不显示（使用 setPayError） | 优化：自动轮询时不显示 |
| "查询失败" | 不显示 | 不显示（自动轮询时） |
| 超时 | `setPayError('支付超时')` | 持续轮询，等待用户返回 |

## 八、事件触发点汇总

| 事件 | 调用的函数 | showError | 说明 |
|------|-----------|-----------|------|
| 自动轮询 `startPaymentPoll` | `handleRefreshStatus(false)` | false | 每3秒一次 |
| 窗口关闭检测 | `handleRefreshStatus(false)` | false | 用户关闭支付宝窗口 |
| 页面获得焦点 `handleWindowFocus` | `handleRefreshStatus(false)` | false | 用户切换回页面 |
| 页面可见性变化 `handleVisibilityChange` | `handleRefreshStatus(false)` | false | 用户切换标签页 |
| 用户点击"刷新状态"按钮 | `handleRefreshStatus(true)` | true | 用户主动操作 |
| localStorage 变化 | `checkPaymentResult()` | N/A | 支付成功通知 |

## 九、修改记录

### 9.1 V7.4.1 优化（当前版本）

**问题 1**：自动轮询时频繁显示"没有支付信息"等错误提示，干扰用户体验。

**修改内容**：

1. `handleRefreshStatus` 添加 `showError` 参数
2. 自动轮询场景传入 `showError: false`
3. 用户主动操作保留错误提示
4. `handlePayModalClose` 停止所有轮询

**问题 2**：轮询提前停止，导致商户页面无法检测支付状态。

**原因**：`startPaymentPoll` 检查 `state.currentPayment` 是否存在，如果不存在就停止轮询。但 `handleRefreshStatus` 内部有逻辑：如果 `currentPayment` 为空，会检查 URL 中的 `out_trade_no` 参数并继续查询。

**修复**：只要弹窗打开且未成功，就继续轮询，不提前停止。

**问题 3**：订单状态是 `cancelled` 时轮询跳过，但用户可能已支付。

**原因**：轮询检查 `status !== 'pending'` 时跳过查询，但 `cancelled` 状态可能是订单超时导致的，实际上用户可能已经支付成功。

**修复**：只有终态才跳过轮询：`paid`, `completed`, `failed`, `expired`。

**问题 4**：跨域读取 `window.location.href` 抛出 SecurityError。

**原因**：尝试读取跨域窗口的 `location.href` 时被浏览器阻止。

**修复**：使用 try-catch 保护。

```typescript
let windowLocation = '无法读取（跨域）'
try {
  windowLocation = windowRef.location?.href?.substring(0, 50)
} catch (e) {
  windowLocation = '跨域受限'
}
```

**影响范围**：
- ✅ 二维码支付：完全不受影响
- ✅ 跳转支付：自动轮询时不显示"没有支付信息"
- ✅ 跳转支付：即使 currentPayment 为空，只要 URL 有 out_trade_no 就继续轮询
- ✅ 跳转支付：`cancelled` 状态时继续轮询
- ✅ 跨域窗口操作不报错

### 9.2 保留的错误提示

以下错误提示不受影响（用户主动操作时才会显示）：
- "缺少查询参数"
- "查询失败"
- "充值配置加载失败"
- "最低充值金额为 X 元"
- "最高充值金额为 X 元"
- "刷新二维码失败，请稍后重试"
- "支付处理失败"
- "支付链接生成失败"

## 十一、注意事项

1. **不要混淆两种轮询**：二维码支付和跳转支付使用完全独立的轮询机制
2. **localStorage 只用于跳转支付**：`checkPaymentResult` 会跳过有 `qr_code` 的支付
3. **窗口关闭检测只用于跳转支付**：二维码支付不打开新窗口
4. **自动行为不显示错误**：轮询、窗口检测、焦点切换等自动行为不干扰用户
5. **用户操作显示错误**：点击按钮等主动操作才显示错误提示

## 十二、跨域通信问题

### 12.1 问题描述

当使用 ngrok 等内网穿透工具时，PaymentSuccess 页面和商户页面可能运行在不同域名：

| 页面 | 域名示例 |
|------|---------|
| 商户页面 | `localhost:3000` |
| PaymentSuccess | `xxx.ngrok.io` |

### 12.2 跨域限制

由于浏览器同源策略限制，以下通信方式**无法跨域工作**：

| 通信方式 | 原因 |
|---------|------|
| `localStorage` | 同源策略，不同域名无法共享 |
| `window.opener.postMessage()` | `window.opener` 指向的是支付宝，而非商户页面 |
| `BroadcastChannel` | 同源策略限制 |

### 12.3 解决方案

**主要方案：后端轮询（最可靠）**

商户页面通过持续轮询后端 API 来检测支付状态，不依赖跨域通信：

```typescript
// startPaymentPoll - 每3秒轮询一次
const startPaymentPoll = () => {
  paymentPollIntervalRef.current = setInterval(() => {
    const state = paymentStateRef.current
    if (state.payModalVisible && !state.paySuccess && state.currentPayment) {
      if (payment.status === 'pending') {
        handleRefreshStatus(false)  // 查询后端状态
      }
    }
  }, 3000)
}
```

**调试方法**：

打开浏览器控制台（F12），查看日志：

```
[Recharge] 启动支付结果轮询（每3秒一次）
[Recharge] 轮询查询支付状态...
[handleRefreshStatus] 自动轮询结果: { queryKey: "PAY...", status: "paid", ... }
```

如果看到：
- `[Recharge] 查询失败: ...` → API 请求失败
- 状态一直是 `pending` → 后端状态未更新

### 12.4 排查步骤

1. **确认轮询是否启动**
   - 控制台搜索 `[Recharge] 启动支付结果轮询`
   - 如果没有，检查订单创建是否成功

2. **确认查询是否成功**
   - 控制台搜索 `[handleRefreshStatus] 查询结果`
   - 如果查询失败，查看具体错误

3. **确认后端状态**
   - 访问 Swagger 文档
   - 调用 `GET /api/v1/payment/status/{payment_no}` 查询状态
   - 确认状态是否为 `paid` 或 `completed`

### 12.5 临时解决方案

如果测试时遇到问题，可以临时关闭自动轮询优化，显示所有错误：

```typescript
// 将所有 handleRefreshStatus(false) 改为 handleRefreshStatus(true)
```

**注意**：仅用于调试，生产环境应恢复优化设置。
