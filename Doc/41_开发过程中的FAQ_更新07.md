## 问题151：数据库时间与本地时间统一

**更新时间**：2026-05-08

### 151.1 问题描述

**用户反馈**：
1. 主动刷新二维码失败
2. 前后端倒计时不同步，显示剩余时间不准确
3. 对账和充值记录时间不统一

### 151.2 问题分析

**根本原因**：
1. **Naive datetime 问题**：代码中使用 `datetime.utcnow()` 返回的是 naive datetime（无时区信息），数据库存储时间与实际 UTC 时间不一致
2. **时区混淆**：
   - 服务器时区为 Asia/Shanghai（UTC+8）
   - 代码使用 `datetime.utcnow()` 返回的时间被当作本地时间处理
   - 导致时间计算偏差 8 小时
3. **前后端时间基准不同**：
   - 前端使用页面加载时间开始倒计时
   - 后端使用数据库 `created_at + 10分钟` 判定过期
   - 两者时间基准不一致

**问题代码示例**：
```python
# 错误：返回 naive datetime
created_at = Column(DateTime, default=datetime.utcnow)

# 错误：naive datetime 比较
if datetime.utcnow() > expiry_time:
    raise ValidationError("订单已过期")
```

### 151.3 解决方案

#### 151.3.1 添加 UTC 时间辅助函数

**修改文件**：`src/utils/helpers.py`

**修改内容**：
```python
def utc_now() -> datetime:
    """
    获取当前 UTC 时间（aware datetime，带时区信息）
    用于代码中获取当前时间

    Returns:
        datetime: 当前 UTC 时间（带 timezone.utc 时区信息）
    """
    return datetime.now(timezone.utc)


def get_utc_now() -> callable:
    """
    返回一个用于 SQLAlchemy default 参数的可调用对象
    SQLAlchemy 要求 default 必须是可调用对象，不能是具体值

    Usage:
        created_at = Column(DateTime, default=get_utc_now())

    Returns:
        callable: 返回当前 UTC 时间的可调用对象
    """
    return lambda: datetime.now(timezone.utc)
```

#### 151.3.3 修复支付订单过期检查

**修改文件**：`src/services/payment_service.py`

**修改内容**：
```python
if payment.created_at:
    from datetime import timedelta, timezone
    # 将 naive UTC datetime 转换为 aware datetime 以便正确比较
    created_at_utc = payment.created_at.replace(tzinfo=timezone.utc)
    expiry_time = created_at_utc + timedelta(minutes=10)
    now_utc = datetime.now(timezone.utc)
    if now_utc > expiry_time:
        raise ValidationError("订单已过期，请重新下单")
```

### 151.4 时间处理原则

| 场景 | 处理方式 | 说明 |
|------|---------|------|
| 数据库存储 | UTC 时间 | 使用 aware datetime（带时区信息） |
| 代码获取当前时间 | `datetime.now(timezone.utc)` | 明确的 UTC 时间 |
| 时间比较 | 统一用 UTC 时间比较 | 确保时区一致性 |
| 前端显示 | 转换为本地时区 | 根据用户浏览器时区显示 |
| API 返回 | 后端计算 `expires_in` | 前端直接使用，避免时区转换 |

### 151.7 Naive vs Aware Datetime 区别

```python
# Naive datetime（无时区信息）- 问题根源
>>> from datetime import datetime
>>> datetime.utcnow()
datetime.datetime(2026, 5, 8, 1, 24, 30, 123456)  # 无 tzinfo

# Aware datetime（有时区信息）- 正确做法
>>> from datetime import datetime, timezone
>>> datetime.now(timezone.utc)
datetime.datetime(2026, 5, 8, 1, 24, 30, 123456, tzinfo=datetime.timezone.utc)

# 时间比较问题
>>> import datetime
>>> naive = datetime.datetime(2026, 5, 8, 9, 24)  # 假设是 UTC 时间
>>> aware = datetime.datetime(2026, 5, 8, 9, 24, tzinfo=datetime.timezone.utc)
>>> naive > aware  # RuntimeWarning: comparison of naive and aware datetimes
```

## 问题152：支付界面渲染逻辑错误 - 跳转支付错误显示二维码

**更新时间**：2026-05-09

### 152.1 问题描述

**用户反馈**：当选择跳转支付方式时，系统错误地显示了二维码支付界面，导致用户无法进行跳转支付。

**问题现象**：
- 用户选择"跳转支付"后，界面仍显示二维码和扫码支付提示
- 缺少"打开支付页面"按钮，无法跳转到支付宝
- 底部提示显示"请耐心等待自动确认"而非"请手动关闭支付宝窗口"

### 152.2 问题分析

**根本原因**：渲染条件判断不完整

在 `Recharge.tsx` 中，判断显示二维码还是跳转支付的逻辑仅检查了支付状态，未验证 `qr_code` 字段是否实际存在：

```typescript
// 原代码 - 只检查了支付状态，未检查 qr_code 是否存在
{currentPayment?.qr_code ? (
  // 显示二维码
) : (
  // 显示跳转支付
)}
```

**问题场景**：当支付方式为跳转支付时，`qr_code` 可能为空字符串 `""`，导致条件判断错误地进入二维码分支。

### 152.3 解决方案

**修改文件**：`api-platform/web/src/pages/developer/Recharge.tsx`

**修改方案**：在渲染条件中添加 `&& currentPayment.qr_code.length > 0` 检查，确保只有当 `qr_code` 实际存在且非空时才显示二维码界面。

#### 152.3.1 修改位置一：二维码/跳转支付界面切换（第1909行）

**修改前**：
```typescript
{currentPayment?.qr_code ? (
```

**修改后**：
```typescript
{currentPayment?.qr_code && currentPayment.qr_code.length > 0 ? (
```

#### 152.3.2 修改位置二：底部提示文字条件（第1988行）

**修改前**：
```typescript
{currentPayment?.qr_code
  ? '提示：支付完成后请耐心等待，系统将自动确认'
  : '提示：支付完成后请点击"刷新状态"确认支付结果'}
```

**修改后**：
```typescript
{currentPayment?.qr_code && currentPayment.qr_code.length > 0
  ? '提示：支付完成后请耐心等待，系统将自动确认'
  : '提示：支付完成后请点击"刷新状态"确认支付结果'}
```

### 152.4 处理前后对比表

| 对比项 | 修改前 | 修改后 |
|--------|--------|--------|
| **二维码界面触发条件** | `currentPayment?.qr_code`（只要字段存在就显示） | `currentPayment?.qr_code && currentPayment.qr_code.length > 0`（字段存在且非空才显示） |
| **跳转支付场景** | `qr_code=""` 时仍显示二维码 | 正确显示跳转支付按钮 |
| **底部提示判断** | 仅检查字段存在性 | 同时检查字段存在性和非空性 |
| **支付按钮显示** | 可能被错误隐藏 | 根据实际支付方式正确显示 |
| **代码位置** | 第1909行、第1988行 | 同上 |
